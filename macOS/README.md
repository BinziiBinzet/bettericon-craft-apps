# BetterIcon for Mac

BetterIcon 1.30.0 is a Universal app for Apple silicon and Intel Macs running macOS 12.4 or later. The disk image carries the list of 41 packs and a small preview of each. A pack downloads when you choose it. After an upgrade from an edition that carried every pack, BetterIcon downloads the packs you had chosen again at the first start, so both pickers open as you left them. Without a connection it keeps your choices and tries again at the next start or pack refresh.

On a new installation the window offers once, under the tabs, to download all app icon packs, all file type icon packs, or both, each with its download size. In a small Launcher window the offer takes one line, and **Download icon packs…** shows the whole choice in **Manage Icons**. **Not now** leaves every pack to download when you choose it. The packs download one after another while you keep using BetterIcon. The place of the offer under the tabs, and the status line under the buttons in **Manage Icons** beside any other news, show the progress. At the end they say how many packs downloaded and name, by cause, up to three packs that could not be downloaded; the others still download, and such a pack downloads when you choose it. When GitHub cannot be reached at all, the downloads stop at once with one sentence that says so. The outcome stays until you close it. If you quit while the packs download, the rest download at the next start. An upgraded installation never sees the offer, also one from a version that never saved a preference.

VimiummuimiV’s eight Modern Flat variants appear as one 13-icon pack. BetterIcon remembers the app icon pack and the file type icon pack separately. If your downloaded artwork differs, it stays usable offline and shows **Update available** until you select the pack.

## Install and use

Open the disk image, drag **BetterIcon** into Applications, then open it. Press **Control–Option–A (⌃⌥A)** to open the launcher at the pointer. You can also click the BetterIcon menu bar icon. The lower-left corner of **Launcher** shows your current shortcut. Click it to change or disable the shortcut, or choose **Change hotkey…** from the menu bar icon. Upgrades keep your saved choice.

While VoiceOver is on, BetterIcon releases ⌃⌥A so VoiceOver can use it for **Read All**. BetterIcon registers the shortcut again when VoiceOver turns off and the keys are available. [Apple’s VoiceOver reading commands](https://support.apple.com/guide/voiceover/read-text-vo2706/mac)

Drag the diagonal grip just inside the lower-right corner, or drag a window edge. **Launcher** and **Manage Icons** each remember their dimensions across restarts. Launcher can shrink to 300 × 240 points. Manage Icons needs 790 × 570 points when the screen allows. Switching tabs keeps their divider at the same screen position. Clicking the menu bar icon opens the tab with the larger saved window area, with Launcher winning a tie. The keyboard shortcut always opens Launcher.

Choose **Exit BetterIcon** in the menu bar icon's right-click menu to quit the app and release its shortcut.

BetterIcon opens at login. On macOS 13 and later the first start of this version adds it to the login items in System Settings, once: **General > Login Items & Extensions** on macOS 15 and later, **General > Login Items** on macOS 13 and 14. Turn it off or on with **Open at Login** in the menu bar icon's right-click menu, or with **Open at login** in **Manage Icons**. The checkmark shows what macOS reports. After you turn it off, here or in System Settings, BetterIcon never adds itself again. It keeps that choice in `choices.json` beside its preferences, which earlier versions never rewrite, so running an earlier version does not undo it. If macOS asks you to allow it, a note under the tabs says where until you have, and its **Open Login Items** button opens that pane; choosing **Open at Login** in the menu while macOS waits opens it too. A copy opened from the disk image is not added: choosing **Open at Login** there says why in **Manage Icons**, and the copy adds itself at its first start from your Applications folder. macOS 12 has no **Open at Login** option, so BetterIcon leaves it out there; you can add BetterIcon in **System Preferences > Users & Groups > Login Items** yourself.

When macOS opens BetterIcon at login, it waits in the menu bar without showing its window. It recognizes that start by the Apple event that opens it: macOS marks a login item launch with keyAELaunchedAsLogInItem in the event's keyAEPropData parameter, which a start from Finder, the Dock, Spotlight or `open` does not carry. The same mark on a reopen event, when macOS opens the login item while BetterIcon already runs, does not show the window either.

1. Open **Manage Icons** and choose an **App icon pack**. Manage Icons previews it. The Launcher changes when you apply the pack, and then shows that pack’s icons. Updating the applied pack does not change the Launcher: each app keeps the artwork that was applied to it until the next Apply.
2. Click **Apply icons…**. Choose **Everywhere** to cover every location, **All users** for apps in the main Applications folder or **Current user** for apps in your home Applications folder and Desktop. The review shows each app or Finder alias, its full path, and the proposed change. A missing assignment leaves that app’s icon in place.
3. Confirm the review to apply the artwork. BetterIcon sets the Finder custom icon on the actual application bundle. Finder, Dock references, and other clients that read the system app icon can pick up the change. A running app can supply its own Dock image. Most ArtCraft apps do, so the Dock shows their original icon while they are open and the pack’s icon again once they quit. ArtCraft Launcher also draws its internal catalog from its own artwork.
4. Use **Restore app defaults…** in the same location to restore the icons that existed before the first Apply. Restoring one location leaves the apps in the other as they are. Right-click an app in either tab to restore just that app. BetterIcon preserves pre-existing custom artwork and reports conflicts if another app or user changes it.
5. ArtCraft Launcher and the apps’ own updaters install each new version as a fresh copy, which drops the custom icon. BetterIcon puts your icons back after app updates by itself: within a second or two while it is running, and when it starts for apps that were updated while it was closed. It also looks every 30 minutes. Each copy gets back the artwork that was applied to it, so apps in both Applications folders can keep different packs. The status line under the buttons in **Manage Icons** names the apps that got their icons back. An app you restored, or whose custom icon you removed yourself in Finder, keeps its original icon. An icon you give an app yourself stays, and after the app’s next update BetterIcon leaves it at its original icon. If macOS stops the change, the status line says so until the app has its icon: turn on BetterIcon in System Settings > Privacy & Security > App Management, then quit and reopen BetterIcon. If you quit while BetterIcon is putting an icon back, it first finishes that app. A running app can still show its own Dock icon until it quits.
6. A new ArtCraft app that appears in a location your last **Apply icons…** covered gets the applied pack’s icon by itself, the same way Apply gives it, with a backup of its own icon, so **Restore** works on it as on any other app. BetterIcon looks when it starts, within a second or two of an install while it runs, and every 30 minutes, when it also finds apps in folders that appeared since. The status line names the apps it gave the pack, together for two minutes. It waits until an install or a copy into the folder has finished, that is, until the app’s Info.plist is there and its code signature checks out; a copy that writes the bundle file by file is looked at again until it has. From then on it leaves alone an app that arrives with a custom icon of its own, also after the app’s next update or once you remove that icon, apps you restored one at a time, also as a renamed, moved or duplicated copy, and apps whose icon you removed in Finder, also once renamed or moved, until an Apply gives that app the pack again. It leaves alone locations the last Apply did not cover or that you restored since, a folder you included after the last Apply (the apps already in it wait for the next Apply, which covers that folder from then on), apps outside the apps folders (both Applications folders, the top level of the Desktop and the folders you included before the last Apply), such as one running from a build folder, and every app after **Restore app defaults**, also after an Apply of a single app from the command line. For an Apply made before this version, the locations where BetterIcon keeps icons count as covered: BetterIcon works them out once, at its first look for apps. If an earlier version later saves the preferences without them, new apps wait for the next Apply. The Launcher draws each copy with the artwork BetterIcon put on it, and an app that carries an icon you gave it, or another custom icon BetterIcon did not set, with that icon. After an update of the applied pack, a newly installed app gets the updated artwork, while apps that already had the pack keep the earlier artwork until the next Apply.

BetterIcon finds ArtCraft bundles in both Applications folders, top-level Desktop apps and Finder aliases, running apps, and existing Dock references. **Include another apps folder…** adds a custom installation location. macOS can ask for Desktop or App Management access. Applying requires write access to the listed item. The review identifies read-only apps.

The icon change uses Finder metadata on the app. Its executable, signed resources, and document associations keep their original contents. Strict code-signature verification can flag the added Finder metadata while an icon is applied. Restoring the original icon also restores that metadata. [Apple’s custom-icon API](https://developer.apple.com/documentation/appkit/nsworkspace/seticon%28_%3Aforfile%3Aoptions%3A%29) · [Apple’s code-signing note](https://developer.apple.com/library/archive/qa/qa1940/_index.html) · [ArtCraft Launcher’s catalog artwork](https://github.com/storytold/craft-launcher/blob/9f950e01ef728a3d32d997d59607051dee98a51d/crates/core/src/catalog.rs#L193)

## Launcher and packs

Type the beginning of an app name, use the arrow keys, and press Return to launch. A single click opens an app. Hovering or choosing it with the keyboard lightens the icon artwork. While you hold the mouse button, the artwork is slightly smaller and darker. Escape clears the filter and then hides the window. Control-scroll over the launcher to change icon size. **Launcher icon size**, its numeric field, Reset, and Show app names affect both tabs. Drag the popup edges to resize.

Import folders or Windows BetterIcon ZIPs, create personal packs, or right-click an icon and choose **Choose icon…**. Editing a built-in creates a personal copy. Right-click either pack selector for **Customize**, **Edit pack**, and **Export ZIP**. **Remove app pack** and **Remove file pack** remove the pack chosen in each list, and **Restore built-in packs** brings hidden built-in packs back. Exports preserve author credits and original SVG, ICO, or PNG artwork. Mac-only ICNS files become PNGs when shared with Windows. WebP artwork is accepted, preferred over a PNG of the same icon, and kept as PNG. Animated WebP is not accepted. Packs can include a custom ArtCraft Launcher icon.

A published pack can offer an icon as WebP, PNG or both. From 1.29.0 BetterIcon downloads one file per icon, the WebP when there is one, and fetches the pack's PNG files only when one of its WebP files cannot be used. From 1.29.1 an update takes every file an earlier download of the pack still holds unchanged from this Mac, fetches only the rest, and then removes the earlier download; shortly after each start BetterIcon also removes copies that updates with earlier versions left behind. BetterIcon uses the WebP and falls back to the PNG of the same icon when the WebP cannot be used: when it is animated, damaged or incomplete, more than 4096 pixels on a side, or not a WebP image at all. An icon with no usable file is left out, and after you choose the pack the status line names it with the reason, for example “App icon pack selected. Left out: PhotoCraft. Animated WebP artwork is not supported.” The Mac reads WebP with ImageIO, which does not notice damage behind an intact header, so such an icon shows blank or garbled instead of falling back. Hover a pack name for up to three sample icons, starting with ArtCraft Launcher when available. In the file type list the samples are the pack’s file icons. Packs are listed by author, then by name, and ArtCraft Launcher leads the Launcher and each pack’s icons. A pack downloads when you click its name or press Return. The label changes to **Downloaded** once the pack is ready. Click the repeat-arrows button at the right of the two pack lists to refresh them. **Refresh available icon packs** is also in the menu bar icon’s right-click menu.

BetterIcon checks for new or updated packs when it starts and about every 30 minutes while it runs. A blue dot on the refresh button signals changes. Refresh the list to see what’s available, then choose which packs to download.

**File type icon pack** sits beside **App icon pack**. It lists the packs that draw file icons: Komplett’s five document packs, Mike22’s three CraftApps AIO November sets, and personal packs with file artwork. The chosen file type pack previews next to the app pack. BetterIcon recognizes 96 extensions, each with its own optional artwork. For example, `FileTypes/glb.png` gives GLB its own icon. Older packs can still draw GLB with their OBJ design. A pack can draw one design for a format (`FileTypes/pcraft.png`) or one for all of an app’s listed formats (`FileTypes/PhotoCraft-PSD.png`). Art named `FileTypes/PhotoCraft-files.png` also draws other file types; see **Other file types** below. For these listed formats the Mac does not look at which app opens a file: a PNG that opens in Preview still takes the PNG design.

macOS takes a file type’s icon from the app that opens it, so a pack cannot set one icon for a whole file type. BetterIcon puts a custom icon on each file instead. **Apply file icons…** asks which files to change. Choose a folder to cover every matching file in it and its subfolders. BetterIcon then keeps that folder up to date: while it runs, and each time it starts, new files there get the pack’s icon. The line under the file type pack shows how many folders are kept up to date. A file that already has an icon of its own is left alone. Apps and other packages, such as an `.rtfd` document or a Photos library, which Finder shows as one item, are never offered and never changed inside: a folder pass and the watcher skip them, and hidden folders too. A kept folder inside another kept folder keeps its own pack. A file whose icon comes from a folder kept up to date belongs to that folder, so **Apply file icons…** leaves it alone and says why. When the pack of a kept folder changes while BetterIcon runs, through an edit, a download, an update or a refresh, the folder’s files follow at once. The confirmation names each chosen file that gets nothing, with the reason. Changing an icon keeps the file’s contents and its modification date, but it does change the file’s metadata, which a sync service such as Dropbox or iCloud Drive will notice. A custom icon also takes the place of Finder’s preview of the file’s contents.

**Other file types.** Art named `FileTypes/<App>-files`, such as `FileTypes/PhotoCraft-files.png`, also draws the file types outside BetterIcon’s list. A file whose extension is not one of the 96 takes that art when the app macOS opens it with by default is that ArtCraft app. BetterIcon asks macOS about each file, so a file you gave another app with **Open with** in Get Info counts. One space, underscore, dot or hyphen may separate the app’s name from “files”, in any case. Art named for a format, such as `PhotoCraft-PSD.png` in Mike22’s packs, Komplett’s app icons, and an app whose art comes in several files of which any is named for a format, stay with that app’s listed formats. The listed formats keep their rules: a format’s own design first, then the original group design when present, then the art for all of its app’s files. The art for other file types never draws a listed extension. Files without an extension, folders, packages, links and Finder aliases, and applications are left alone, and so are files with an icon of their own, as for the listed formats. When the rule no longer holds for a file that has such an icon from BetterIcon, because another app opens it now, the pack has no such art any more, or the file was renamed to a listed format, the next look at that file takes BetterIcon’s icon off again or gives it the design of its format: **Apply file icons…**, a new or changed file in a folder kept up to date, a change to the pack of a kept folder, or the start of BetterIcon. **Apply file icons…** offers files of every type while the file type pack draws other file types, or while files you chose earlier carry such an icon from BetterIcon, and the confirmation for a folder says how many files lose it. An icon you put over BetterIcon’s stays, and BetterIcon leaves that file alone from then on. Only the files you choose and the files in folders kept up to date get these icons; macOS keeps drawing every other file of that type with the icon of the app that opens it. The line under the file type pack names up to two apps whose other files the pack draws, or counts them, for example “27 file types, plus other PhotoCraft files”. A personal pack keeps art named `FileTypes/<App>-files` from a folder or ZIP import as such art, besides filling in the app’s listed formats that have no art of their own. Editing the pack keeps it in a row of its own, which you can clear, and **Export ZIP** writes it as `FileTypes/<App>-files` in its own format (PNG, SVG or ICO; ICNS becomes PNG), so an import opts in again. That import fills in the app’s listed formats without art of their own again, also a format you cleared in the editor. Packs saved by earlier versions never draw other file types.

**Restore file icons…** restores the saved Finder artwork of the files you choose, also of files of other types, whatever app opens them now, and also an icon of their own that a file had before. Choose a folder to remove the icons BetterIcon put on its files and to stop keeping it up to date; while the Restore works, nothing puts an icon back on that folder’s files. An icon you put over one BetterIcon gave a file of another type stays. With **Original file icons** chosen, the one action is **Restore original file icons…**.

Click the version text at the bottom of **Manage Icons** to open the BetterIcon GitHub project in your default browser. The adjacent buttons select BetterIcon’s own icon and cycle Dark, Light, and System appearance. The app takes its colors from the chosen icon. There are twenty choices: ten styles, including Grayscale and High contrast, each in Dark and Light. Choosing a named Dark or Light icon also switches the appearance. **Match app theme** follows the appearance button.

Preferences, personal packs, verified originals and a copy of the artwork applied to each app live in `~/Library/Application Support/BetterIcon`. Keep this folder while using customized icons. You can move or remove BetterIcon itself independently.

## Local builds and checks

Build on a Mac with Xcode Command Line Tools and Go 1.25, from a checkout of this project. The build takes the catalog, the app icons and the hover strips from the checkout and packages no pack artwork. Go and Python are build tools. The installed app includes its catalog helper. The app’s color schemes come from `Shared/themes.json`, which `Windows/Export-Themes.ps1` writes from the Windows app.

~~~sh
./build.sh "$HOME/Downloads/BetterIcon"
./test.sh "$HOME/Downloads/BetterIcon/BetterIcon.app"
~~~

The build produces a locally signed Universal app and a drag-to-install disk image. The local build has no Apple notarization ticket. The test script uses disposable bundles, real Finder metadata, a private pack library, and an offscreen copy of the app interface. It hands the app stand-ins for macOS’s login items and for pack downloads, so it never registers a real login item. One check runs the real download helper through a proxy on the Mac that refuses every connection, so nothing leaves the Mac, and one makes a small disk image and attaches it read-only, without showing it in Finder, to see how a copy opened from a disk image is told apart.

`PackSizes.tsv` lists the download size of each pack in the catalog, for the offer a new installation makes; the catalog itself has no sizes. After `Windows/PackCatalog.tsv` changes, run `python3 macOS/pack-sizes.py` from a checkout that has the pack artwork. It checks every file against the catalog. The build warns, and the checks fail, while the table lists another catalog.

To also test global registration and release, run the test script with `BETTERICON_TEST_HOTKEY=1` on a Mac where ⌃⌥A is available and VoiceOver is off. This briefly registers the shortcut and delivers test events inside the test process.

The checks of the art for other file types hand BetterIcon stand-ins for Launch Services. To also run them end to end, set `BETTERICON_TEST_OPENER` to an empty folder outside the temporary folders, such as one under `~/Library/Caches`: Launch Services never names an app in a temporary folder as a file’s opener. The test then registers two throwaway apps there, each with a made-up bundle ID and its own made-up file type, calls the first one PhotoCraft through a test seam only, and unregisters and deletes both at the end.

The app executable also supports `--list-packs`, `--list-apps`, `--apply`, and `--restore`. Apply and restore print a preview by default. Add `--yes` to write the changes. Run the following for all switches.

~~~sh
"/Applications/BetterIcon.app/Contents/MacOS/BetterIcon" --help
~~~
